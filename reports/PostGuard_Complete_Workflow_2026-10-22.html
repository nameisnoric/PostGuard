1. Master Flow ของระบบ

PostGuard เป็น Desktop Application ที่ประมวลผลภาพกล้องบนเครื่องผู้ใช้ ส่งเฉพาะค่าที่คำนวณแล้วไปยัง FastAPI และจัดเก็บข้อมูลผู้ใช้ Session, Alert และ Report ใน PostgreSQL/Supabase
เปิดโปรแกรม → สมัคร/เข้าสู่ระบบ → ตรวจ Consent และ Session ค้าง
Dashboard → Camera Setup → Preview → Camera Preparation
Personal Baseline → Start Session → Monitoring → Alert
Pause/Resume หรือ Stop → Session Summary → Dashboard / History / Report
1
Identity: ผู้ใช้สมัครด้วยอีเมล @ku.th ยืนยัน OTP แล้ว Login เพื่อรับ JWT
2
Privacy: ระบบตรวจ Privacy Notice และ Consent ก่อนเริ่มงานที่ใช้กล้อง
3
Camera: สแกนกล้อง เปิด Preview และเตรียมกล้องด้วยบัตรมาตรฐาน
4
Baseline: เก็บท่าปกติของผู้ใช้ ตรวจความครบถ้วน/ความนิ่ง และให้ผู้ใช้ยืนยันก่อนบันทึก
5
Session: เริ่ม Monitoring โดยผูก User + Camera + Personal Baseline
6
Detection: ประมวลผล Face/Pose, เปรียบเทียบ Baseline, ติดตามเวลา และคำนวณความเสี่ยง
7
Alert: สร้าง Alert Event, popup และเสียงตาม Settings
8
Report: เมื่อ Stop จะจบ Session บันทึก Summary และแสดงผ่าน Dashboard/History
9
Recovery: หากแอปถูกปิดผิดปกติ ระบบตรวจ Session ค้างเมื่อ Login ครั้งถัดไป

2. Authentication และ Account Flow

Registration

Register → ตรวจ @ku.th + Username + Password/Confirm Password
→ ส่ง OTP ผ่าน Resend → ยืนยัน OTP 6 หลัก → สร้างบัญชี → Login
  • รับเฉพาะอีเมลมหาวิทยาลัยโดเมน @ku.th
  • Password และ Confirm Password ต้องตรงกัน และผ่านเงื่อนไขที่ Backend กำหนด
  • Backend เก็บเฉพาะ Argon2 password hash
  • Resend ใช้ผู้ส่ง PostGuard <no-reply@postguardapp.xyz>

Login

Email + Password → POST /auth/login → JWT
→ TokenStore ในหน่วยความจำ → GET /auth/me → Dashboard

ทุก API ที่เป็นข้อมูลส่วนตัวแนบ Bearer token และ Backend ตรวจเจ้าของข้อมูลอีกครั้ง ผู้ใช้รายอื่นจึงไม่สามารถอ่าน Camera, Baseline, Session, Alert หรือ Summary ข้ามบัญชีได้

Forgot Password

ขั้นการทำงาน
1. Requestกรอก @ku.th → POST /auth/forgot-password → ส่ง OTP อายุ 5 นาที
2. Verifyกรอก OTP 6 หลัก → POST /auth/verify-reset-otp → ได้ reset token อายุ 10 นาที
3. Resetกรอกรหัสผ่านใหม่และยืนยัน → POST /auth/reset_password → token ใช้ได้ครั้งเดียว
Reset token อยู่ใน dialog ชั่วคราว ไม่เก็บใน TokenStore และถูกล้างเมื่อยกเลิกหรือเปลี่ยนรหัสผ่านสำเร็จ

3. Privacy, Profile, Settings และ Account Deletion

Privacy Consent

Login → ตรวจ Consent เวอร์ชันปัจจุบัน
ยังไม่ยินยอม → แสดง Privacy Notice → ยอมรับ → เปิด Camera Flow ได้
  • สถานะการยอมรับ เวอร์ชัน เวลาให้ Consent และเวลาถอน Consent ถูกเก็บต่อผู้ใช้
  • Backend ตรวจ Consent ซ้ำเมื่อเริ่ม Session
  • ไม่อนุญาตให้ถอน Consent ขณะ Session เป็น RUNNING หรือ PAUSED
  • หลังถอน Consent ต้องยอมรับใหม่ก่อนเริ่ม Monitoring ครั้งถัดไป

Profile

การกระทำFlow
แก้ข้อมูลแก้ Username/Full name → กด Save Changes → dialog ยืนยัน → PATCH ข้อมูลผู้ใช้ → refresh profile
รูปโปรไฟล์เลือกภาพ → upload ไป private storage → Backend เก็บ object key → โหลดผ่าน endpoint ที่ตรวจ JWT
ยกเลิกการแก้ออกจากหน้าโดยไม่ส่งข้อมูลที่ยังไม่ยืนยันไป Backend

Settings

Settings บันทึกแยกต่อผู้ใช้ ได้แก่ เปิด/ปิดการแจ้งเตือน เปิด/ปิดเสียง ระดับเสียง และช่วงเตือนให้พัก เมื่อกด Save ระบบส่ง PUT และโหลดค่าที่บันทึกกลับมาแสดง

Delete Account และ Recovery

Settings → Delete Account → ยืนยัน
→ PENDING_DELETION 14 วัน → Logout / จำกัดการใช้งาน
Login ภายใน 14 วัน → Account Recovery → ยกเลิกคำขอลบ

เมื่อครบช่วงรอ ระบบ purge จะลบบัญชีและข้อมูลที่เกี่ยวข้อง หากลบ private avatar ไม่สำเร็จจะเลื่อนการลบเพื่อ Retry แทนการทิ้งไฟล์ส่วนตัวไว้โดยไม่ติดตาม

4. Camera Setup และ Preparation Flow

Camera Setup → Scan Device Index → เลือกกล้อง
→ Camera Preview → ลงทะเบียน/อ่าน Camera ID
→ Camera Preparation ด้วยบัตรมาตรฐาน → Personal Baseline

Camera Scan

  1. เปิด device index ที่กำหนดไว้ทีละตัวด้วย OpenCV
  2. ตรวจว่าอุปกรณ์เปิดสำเร็จและอ่าน frame ได้จริง
  3. เก็บเฉพาะกล้องที่ใช้งานได้ แสดงชื่อ Device และ Resolution ให้ผู้ใช้เลือก
  4. ปล่อย resource ของกล้องที่ใช้ตรวจทุกตัว แล้วเปิดกล้องที่ผู้ใช้เลือกเมื่อเข้าสู่ Preview

Camera Preview

แสดงภาพแบบรักษาอัตราส่วนและจัดกลางกรอบ ตรวจ Face/Pose เพื่อช่วยให้ผู้ใช้เห็นว่าศีรษะและไหล่อยู่ในภาพ หากเปิดหรืออ่านกล้องไม่ได้จะแสดงข้อผิดพลาดและไม่อนุญาตให้ไปขั้นถัดไป

Camera Preparation ด้วย Reference Card

หัวข้อรายละเอียด
บัตรอ้างอิงขนาดมาตรฐาน 85.60 × 53.98 มม.
เงื่อนไขตรวจขนาด ตำแหน่ง อัตราส่วน การหมุน และ perspective
ความต่อเนื่องต้องผ่าน 10 เฟรมติดต่อกัน พร้อมตัวนับ 1/10 ถึง 10/10
ผลลัพธ์frame size, scale X/Y/average, card roll, perspective และ capture time
ความเป็นส่วนตัว: ระบบไม่บันทึกหรืออัปโหลดภาพบัตร frame, contour, card box หรือ transform matrix ส่งเฉพาะค่าตัวเลขไปผูกกับ Personal Baseline

5. Personal Baseline Flow

เปิดภาพกล้อง → ตรวจ Face + Pose
→ Start Calibration → เก็บ Valid Samples
→ ตรวจ Coverage + Ratio + Stability → Candidate
→ ผู้ใช้ยืนยัน → Save Baseline → ได้ baseline_id

ข้อมูลที่ต้องครบ

Measurementการใช้งาน
Shoulder tiltค่าระดับไหล่ซ้าย–ขวาปกติของผู้ใช้
Neck lateral tiltค่าการเอียงคอด้านข้างปกติ
Neck flexionค่าก้ม/เงยคอปกติ
Eye-distance proxyค่าประกอบสำหรับระยะและบริบทของกล้อง

เกณฑ์ผ่าน

  • เก็บอย่างน้อย 60 valid samples
  • ครอบคลุมเวลาอย่างน้อย 15 วินาที
  • สัดส่วน valid frame อย่างน้อย 70%
  • ค่าที่วัดต้องนิ่งตาม stability checks
  • ต้องมี Camera Preparation result ครบและเป็นค่าจำนวนที่ใช้งานได้

เมื่อผ่าน ระบบสร้าง Candidate Baseline โดยใช้ค่ากลางและส่วนเบี่ยงเบนของ measurement แต่ยังไม่บันทึกทันที ผู้ใช้ต้องกดยืนยัน Candidate ก่อน ปุ่ม Save Personal Baseline จึงใช้งานได้ และปุ่ม Start Monitoring จะเปิดหลังบันทึกสำเร็จเท่านั้น

กรณีไม่ผ่าน: ระบบแสดงสาเหตุ เช่น Face/Pose ไม่ครบ ตัวอย่างไม่พอ เวลาไม่ถึง valid ratio ต่ำ หรือค่าท่าทางไม่นิ่ง แล้วให้เก็บ Baseline ใหม่

6. Monitoring และ Detection Pipeline

Start Monitoring → ตรวจ Consent/Baseline → สร้าง Session RUNNING
อ่านกล้องทุก ~30 ms → ตรวจจับทุก 5 เฟรม → Measurement
→ Baseline Comparison → Temporal Tracking → Risk/Alert

Pipeline ภายในหนึ่งรอบตรวจจับ

1
OpenCV อ่าน frame จากกล้องที่เลือก
2
MediaPipe Face/Pose สร้าง landmark และ validator ตรวจคุณภาพข้อมูล
3
Detection Pipeline คำนวณ shoulder tilt, neck lateral tilt และ neck flexion
4
Session Monitor ตรวจว่า Session, Camera และ Baseline เป็นเจ้าของเดียวกันและมีความสัมพันธ์ถูกต้อง
5
Current Posture Assessment เปรียบเทียบค่าปัจจุบันกับ Personal Baseline และ tolerance
6
Measurement Change Gate ลดผลจาก noise และค่าที่เปลี่ยนเพียงเล็กน้อย
7
Temporal Tracker สะสมเวลาต่อเนื่องของ posture factor และ reset เมื่อกลับสู่ท่าปกติหรือ Pause
8
Risk Evaluator สร้างผลประเมินภายใน และ RULA-adapted mapper สร้างคะแนนสำหรับผู้ใช้

สถิติที่อยู่ในหน่วยความจำประกอบด้วยจำนวนรอบตรวจจับ จำนวน Face/Pose ที่พบ ค่าเฉลี่ยของมุม คะแนนความเสี่ยง และข้อมูล Alert ก่อนสร้าง Summary ตอนจบ Session

7. Session Lifecycle และ Navigation

สถานะความหมายและการเปลี่ยนสถานะ
RUNNINGกล้องและ timer ทำงาน → Pause เปลี่ยนเป็น PAUSED → Stop เปลี่ยนเป็น COMPLETED
PAUSEDหยุด timer ตรวจจับและ reset เวลาท่าต่อเนื่อง แต่ยังถือกล้องไว้ → Resume กลับ RUNNING → Stop ได้
COMPLETEDจบโดยผู้ใช้หรือ flow ปิดตามปกติ ปล่อยกล้อง แล้วจึงบันทึก Session Summary
INTERRUPTEDSession เก่าที่ไม่มีการจบอย่างสมบูรณ์ ไม่มีการแต่ง ended_at, duration หรือ Summary ขึ้นมา

การเปลี่ยนหน้า

Monitoring ↔ Dashboard ↔ History
Session และ Detection ยังทำงานต่อ → กลับ Monitoring เพื่อดูภาพหรือควบคุม Session

การเปลี่ยนหน้าไม่เรียก Stop และไม่ทำลาย MonitoringPage ปุ่มส่วนกลางแสดง Pause/Resume/Stop ตามสถานะเดียวกับหน้า Monitoring

Logout หรือปิดโปรแกรม

หากมี Session ทำงาน แอปจะพยายาม End Session และ Save Summary ก่อนปล่อยกล้องและล้าง token หากขั้นตอนใดล้มเหลว แอปคงข้อมูลที่จำเป็นไว้เพื่อ Retry และไม่เริ่ม Session ใหม่ทับ Summary ที่รอบันทึก

Session Recovery

Login ครั้งใหม่ → GET Sessions → พบ RUNNING/PAUSED ที่แอปรอบนี้ไม่ได้ถืออยู่
→ ถามผู้ใช้ → Interrupt หรือ Cancel
  • ไม่ตัดสิน Session ค้างเอง เพราะอาจทำงานอยู่บนอุปกรณ์อื่น
  • POST /sessions/{id}/interrupt ตรวจเจ้าของและรองรับ Retry
  • Alert ที่ยังเปิดอยู่จะแสดง INCOMPLETE และ duration เป็น N/A

8. Alert และ RULA-adapted Flow

Posture Assessment → Temporal Evidence
→ Risk Evaluation → เปิด Alert Event
→ Popup + Optional Sound → ปิด Alert เมื่อท่ากลับปกติ/Session หยุด

Alert Service ป้องกันการเปิด popup ซ้ำจากเหตุการณ์เดียวกัน เสียงทำงานตาม notification, sound และ volume ใน Settings ส่วน Alert Event เก็บชนิด เวลาเริ่ม เวลาปิด และระดับความเสี่ยง

RULA-adapted 1–7

ส่วนเงื่อนไขคะแนน
Neck baseก้ม 0–10° / >10–20° / >20° / เงย <0°1 / 2 / 3 / 4
Neck side bendingเอียงคอเกิน tolerance จาก Baseline+1
Shoulder asymmetryไหล่ซ้าย–ขวาไม่สมดุลเกิน tolerance+1
Sustained postureปัจจัยที่รองรับค้างนานกว่า 60 วินาที+1
คะแนน = Neck base + Neck side bending + Shoulder asymmetry + Sustained posture
จำกัดสูงสุด 7 คะแนน
คะแนนระดับคำแนะนำ
1–2LOWความเสี่ยงต่ำ สังเกตท่าทางต่อไป
3–4MODERATEควรปรับท่าทางและติดตามต่อเนื่อง
5–6HIGHควรปรับท่าทางโดยเร็ว
7VERY HIGHควรหยุดพักและปรับท่าทางทันที
คะแนนนี้เป็นการประยุกต์ RULA กับกล้องด้านหน้า ไม่ใช่ Full RULA หรือผลวินิจฉัยทางการแพทย์ ระบบแสดง N/A เมื่อหลักฐานหลักไม่ครบ

9. Stop, Summary, Dashboard และ History

Stop และ Summary

Stop Monitoring → Snapshot สถิติ → End Session
→ ยืนยัน COMPLETED → ปล่อยกล้อง → POST Summary
→ Session Summary Page หรือ Retry
  • สร้าง Summary หลัง Session เป็น COMPLETED เท่านั้น
  • หนึ่ง Session มีหนึ่ง Summary; หาก POST ซ้ำได้ 409 ระบบอ่านรายงานเดิมกลับมา
  • Total duration รวมเวลาพัก ส่วน Active duration = Total duration − Paused duration
  • Alert duration คือเวลาที่ Event เปิดอยู่ ไม่ใช่เวลาท่าทางเสี่ยงทั้งหมด

Dashboard

ข้อมูลแหล่งและวิธีคำนวณ
Completed sessionsนับ Session สถานะ COMPLETED
Active monitoring timeรวม total_duration − paused_duration ของข้อมูลที่สมบูรณ์
Interrupted sessionsนับ Session สถานะ INTERRUPTED
Risk/Alert summaryอ่านจาก GET /summaries และแยก RULA-adapted /7 ออกจาก legacy /3
Recent sessionsแสดงรายการล่าสุดไม่เกิน 5 รายการ

Dashboard โหลด GET /sessions และ GET /summaries ผ่าน Qt thread pool เพื่อไม่ให้ UI และ timer ตรวจจับค้างระหว่างรอ API

History และ Saved Report

History รองรับค้นหาด้วย Session/Camera/Baseline ID และกรองตามสถานะ เมื่อเลือกแถวจะแสดงเวลาเริ่ม–จบ Total/Paused/Active time, Camera, Baseline และสถานะรายงาน ผู้ใช้เปิด Saved Report หรือ Alert Events ของ Session ที่เลือกได้

Saved Report อ่านข้อมูลที่บันทึกไว้จากฐานข้อมูล ไม่ย้อนกลับไปคำนวณ Detection ใหม่ และจะแสดง N/A สำหรับข้อมูลที่ไม่มีแหล่งจริง

10. Backend, Database และ Data Privacy

สถาปัตยกรรม

PySide6 Desktop → HTTP/JSON + JWT → FastAPI
→ SQLAlchemy/Alembic → PostgreSQL on Supabase
Resend → Registration/Password Reset Email
กลุ่ม APIหน้าที่
AuthRegister OTP, verify OTP, Login, Me และ Password Reset
Users/Privacy/SettingsProfile, private avatar, Consent, preferences และ Account Deletion
Cameras/Baselinesลงทะเบียนกล้องและจัดเก็บค่าตัวเลข Camera Preparation/Personal Baseline
SessionsStart, Pause, Resume, End, Interrupt และ List
Alerts/Summariesสร้าง/ปิด Alert Event และจัดเก็บ/อ่าน Session Report

ข้อมูลภาพ

Local processing: frame จากกล้องใช้ประมวลผลบนเครื่องผู้ใช้ ไม่บันทึกและไม่อัปโหลดวิดีโอหรือภาพ Monitoring ไป Backend คงไว้เฉพาะค่าตัวเลข Session, Baseline, Alert และ Report ที่จำเป็น

Ownership และ Security

  • JWT ระบุผู้ใช้ และ query ทุกชุดจำกัดข้อมูลด้วย user ownership
  • Password จัดเก็บด้วย Argon2 hash
  • OTP/reset token มีอายุและใช้ซ้ำไม่ได้
  • Avatar อยู่ใน private storage และดาวน์โหลดผ่านเส้นทางที่ตรวจสิทธิ์
  • Alembic ควบคุม schema version ของ Supabase

11. Error, Retry, การทดสอบ และการเปิดใช้งาน

เหตุการณ์พฤติกรรมระบบ
กล้องเปิด/อ่านไม่ได้แสดงข้อผิดพลาด ปล่อย resource และไม่ไปขั้นถัดไป
Baseline ไม่ครบไม่สร้าง Candidate หรือไม่อนุญาต Start Session
